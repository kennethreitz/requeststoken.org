02 — Content negotiation

JSON or YAML

The JSON endpoints above, /openapi.json and /health choose a format from the Accept header and send Vary: Accept.

  • application/json, */*, no header — JSON
  • application/yaml, application/x-yaml, text/yaml — YAML (application/yaml)
  • q-values — the higher-quality format wins; q=0 excludes a format
  • Anything else (text/html, image/png…) — JSON with 200, not 406
  • Errors — application/problem+json regardless of Accept (e.g. 404, 405)
  • /metrics — always Prometheus text
curl https://requeststoken.org/api/token
curl -H 'Accept: application/yaml' https://requeststoken.org/api/token
curl -H 'Accept: application/yaml;q=0.9, application/json;q=0.5' https://requeststoken.org/health
curl -H 'Accept: application/yaml' https://requeststoken.org/openapi.json

03 — Operational

Health and metrics

GET /health — readiness: {"status": "ok", "checks": {...}}; 503 when a check fails.

GET /metrics — Prometheus text: request counts, in-flight requests and latency per route.
